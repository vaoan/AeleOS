# Dragging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move things around a page by dragging them — content between places, sections into and out of nesting — by mouse and by keyboard.

**Architecture:** The move is a pure function first: a drag produces a new tree, with the swap-versus-shift rules and the cycle guard, testable with no UI at all. Then `@dnd-kit` replaces `@hello-pangea/dnd`, which cannot express nested drag or grids by its own README.

**Tech Stack:** React 19, `@dnd-kit/core` + `@dnd-kit/sortable`, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-18-dragging-design.md`

**Follows:** `#159`.

## Global Constraints

- **A drop onto an empty place moves; a drop onto an occupied place swaps.** Nothing else shifts. Sections at the top level reorder by shifting, because the page's own list has no empty places to disturb. Insert-and-shift inside a section would move the empty places somebody deliberately left.
- **A container may never be dropped into its own descendant.** The tree is `jsonb` and a cycle is unrepresentable, so the guard belongs where the move is computed, before anything is written.
- **The depth cap of three still binds.** A drag that would exceed it is refused.
- **Keyboard lift, move and drop are not optional.** The two existing end-to-end keyboard specs are **ported, not dropped**, with announcement selectors re-derived from dnd-kit's own output.
- **Four props must not be dropped** — omitting `{...listeners}` or `setNodeRef` kills the drag by mouse _and_ keyboard, silently, and **a mocked test hides it identically** because the mock supplies what the real hook would have. Omitting `{...attributes}` kills only the keyboard, and only on a non-focusable handle.
- **`<DndContext id={useId()}>`.** dnd-kit's id generator is a module-level counter, so two server renders in one warm process emit different ids and every request after the first hydrates mismatched. Invisible in production if forgotten.
- **Nesting is not a switch.** dnd-kit hands you the collision decision; a nesting-naive one resolves `over.id` to a leaf inside the hovered container and the container reorder silently never fires. **Depth three is unproven** — the spike's detector was two-level-specific.
- **Filter test output.** Run the suite you are changing, summary line only; expand to detail for a specific failure. A full run that dumps every stack trace costs enormously and tells you nothing the summary did not until something breaks.
- **One agent per working tree.** Staging your own files protects the index and protects nothing about a gate run against a tree somebody else is editing.
- Every export carries TSDoc stating the contract. 100% coverage including branches; `vitest.config.ts` excludes `src/features/*/presentation/**`, so presentation needs **named** tests.
- **Cold-start the dev server**; a stale `next dev` serves stale message modules. Neither `pnpm test:e2e` nor bare `npx playwright test` loads `apps/hub/.env.local`.
- Branch: `git checkout -b feat/dragging origin/main`.

### Task 1: the move, with no dragging in it

**Files:** `apps/hub/src/features/actors/domain/block-moves.ts` (create), its test

The semantics, as pure functions. **No UI, no library, no drag** — a move is a source path, a target path, and a tree in, a tree out.

- [ ] **Step 1: Write the failing tests**

Moving onto an empty place leaves the source empty. Moving onto an occupied place swaps exactly two things and touches nothing else. A top-level section reorder shifts. A move into a descendant of itself is refused. A move that would exceed the depth cap is refused. A move to and from the same place is a no-op that returns the same tree.

- [ ] **Step 2: Run and watch them fail**
- [ ] **Step 3: Implement**
- [ ] **Step 4: Sabotage-verify the cycle guard** — remove it and watch the case fail rather than hang. If it hangs instead, the test is wrong: assert the refusal, not the absence of a crash.
